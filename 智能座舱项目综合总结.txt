## 2.1 项目背景

随着智能网联汽车快速发展，智能座舱已成为汽车"新四化"（电动化、智能化、网联化、
共享化）战略的核心载体。当前主流的智能座舱方案高度依赖云端 AI 服务，普遍存在
三大痛点：

  1. 网络依赖性强 —— 隧道、山区等无网环境功能降级甚至失效；
  2. 隐私安全风险 —— 车内语音/视频数据上传云端，用户隐私难以保障；
  3. 响应延迟不可控 —— 云端往返延迟影响安全预警的实时性。

本项目基于龙芯 LoongArch 架构的端侧 AI 计算能力，构建"全离线、低延迟、高隐私"
的智能座舱多模态交互终端。核心创新点在于将语音交互、视觉感知、大模型推理尽可
能部署在车规级龙芯终端上，实现真正意义上的"端侧智能"。

## 2.2 项目目标

设计文档中设定的量化目标如下：

  | 目标维度         | 指标              |
  |------------------|-------------------|
  | 语音唤醒率       | ≥ 95%（车载噪声） |
  | 语音识别准确率   | ≥ 93%（端侧 ASR） |
  | 疲劳检测准确率   | ≥ 90%（多模态）   |
  | 意图识别准确率   | ≥ 88%（本地 NLU） |
  | 语音响应延迟     | ≤ 500ms（端到端） |
  | 危险预警延迟     | ≤ 200ms           |
  | 大模型推理速度   | ≥ 15 tokens/s     |

（注：以上为目标值；当前原型在 x86 上运行，端侧指标尚未在龙芯硬件上实测达标。）

## 2.3 产品定位

  产品定位：一款面向驾驶员的多模态智能座舱交互终端，集"安全守护 + 情感陪伴 +
  语音秘书 + 座舱控制"于一体。

  四大核心角色：
    1. 安全驾驶守护 —— 疲劳/分心实时检测与分级告警；
    2. 情感陪伴助手 —— 表情识别与个性化情感响应；
    3. 智能语音秘书 —— 唤醒词交互、语音点歌、天气/导航查询；
    4. 座舱控制中枢 —— 自然语言车控（空调/车窗/座椅/灯光等）。

## 2.4 两个项目的演进关系

  项目经历了从"原型验证"到"工程落地"的两代演进：

  第一代 smart_cockpit（"小航"，mengchuang）：
    · 形态：Python 单体应用（Gradio + Flask MJPEG），快速验证功能可行性；
    · 特点：本地推理（表情 ONNX、安全 PERCLOS、ASR faster-whisper）+ 云端
      能力（DeepSeek 对话、edge-tts 合成）；
    · 局限：单文件 app_demo.py 体量庞大（6 万字节级），前后端耦合，不利于
      工程化与多人协作。

  第二代 smart_seat（"小龙"）：
    · 形态：前后端分离三层架构（React 前端 + FastAPI 后端 + Flask 摄像头服务）；
    · 特点：模块化、可扩展，新增仪表盘、天气、音乐娱乐、座舱控制等页面；
    · 目标：面向龙芯板卡的实际部署与挑战杯展示。

  二者共享的技术底座：ONNX EfficientNet-B2 表情模型、PERCLOS/哈欠疲劳检测、
  DeepSeek 对话、TTS 语音合成；smart_seat 进一步引入 MediaPipe FaceLandmarker
  （468 关键点）、SQLite 持久化、WebSocket 车辆数据推送、Whisper ASR 服务。

  | 表情识别   | ONNX EfficientNet-B2 7 类情绪 + MediaPipe 规则双引擎       |
  | 语音助手   | 唤醒词 + 浏览器/Whisper ASR + DeepSeek AI 对话             |

  | 音乐娱乐   | 本地曲库扫描 + Jamendo 在线曲库 + 语音点歌 + 全局播放器   |

## 3.2 仪表盘模块

  功能需求：
    · 主车速表：0~240 km/h 指针式仪表，含刻度与数字读数；
    · 运行参数：转速 RPM、油量 %、水温 ℃、电量 % 四个迷你仪表；
    · 胎压监测：左前/右前/左后/右后四轮胎压，异常变色告警；
    · 车辆数据：总里程、电池电量、续航里程、平均能耗；
    · 驾驶控制：开始驾驶 / 停车按钮，怠速计时。

  数据来源：WebSocket 推送 + 后端硬件模拟器（hardware_sim.py）。

## 3.3 疲劳检测模块（安全驾驶核心）

  功能需求（当前为事件驱动告警版本 v6）：

    · 眼闭合检测：基于 Eye Aspect Ratio（EAR，MediaPipe 眼周关键点），阈值 0.20；
    · 哈欠检测：基于 Mouth Aspect Ratio（MAR，嘴部关键点），阈值 0.6；
    · 事件 → 告警映射：
        - 哈欠          → warning（轻度）  → 播报"请集中注意力，认真驾驶"；
        - 闭眼 > 2s     → high（中度）     → 播报"您有些疲劳了，请注意休息"；
        - 闭眼 > 4s     → critical（重度） → 播报"危险！请立即停车休息"；
    · 疲劳评分：仅作参考展示值（分层：哈欠=30、闭眼 high=65、critical=85），
      不参与告警触发；
    · 告警冷却：哈欠冷却 30s、闭眼冷却 15s、告警最短保持 3s；
    · 视线方向：三态分类（forward / down / left / right / dashboard / mirror），
      仅展示用。

  关键设计原则（对话中反复确认）：语音播报由"事件"驱动，而非"分数"驱动；
  疲劳评分只是"摆设"，无论分数多高都不应触发播报。

## 3.4 表情识别模块

  功能需求：
    · 7 类情绪分类：angry / disgusted / fearful / happy / neutral / sad / surprised；
    · 双引擎：ONNX EfficientNet-B2 深度学习 + MediaPipe 规则引擎兜底；
    · 悲伤增强后处理（提高 sad 召回）；
    · 情绪统计与历史记录（SQLite 持久化，可查近 N 天分布）；
    · 情绪驱动的座舱联动建议（氛围灯、音乐音量、座椅温度等）。

## 3.5 语音助手模块

  功能需求：

## 5.5 疲劳检测技术方案（演进历程）

  检测输入：MediaPipe FaceLandmarker 提取 468 个人脸关键点。

  · EAR（眼部长宽比）计算：取左眼(33,133,159,145)与右眼(362,263,387,373)的
    上下/左右距离比，二者取均值；阈值 0.20 判定闭眼。
  · MAR（嘴部长宽比）计算：上唇(13)/下唇(14)距离 ÷ 嘴角(61)/嘴角(291)距离；
    阈值 0.6 判定哈欠。
  · PERCLOS：眼睑闭合时间占比（设计阶段用于疲劳评分参考）。

  算法演进：
    v1/v2   —— 评分驱动：多特征加权（PERCLOS 70% + 哈欠 30% 等）算疲劳分，
               再由分数映射告警等级，前端 EWMA + Sustain Gate 平滑；
    v6      —— 事件驱动：废弃评分管线，直接由事件（哈欠/闭眼）决定告警等级，
               评分仅作参考展示；
    v6+分层 —— 评分改为分层值（闭眼 high=65/critical=85/哈欠=30），避免"一闭眼
               就涨到 100"。

  遗留讨论（对话中已定位、最终回退未合并）：
    · 前端在摄像头数据不新鲜时会退化为"驾驶时长 + 模拟指标"算分并反推告警，
      导致"分数触发播报"——正确做法是语音循环严格 gate 在 camFresh 上；
    · 后端哈欠单帧触发，导致"张嘴表情误判成哈欠"——正确做法是加 MAR 持续
      ≥1.5s 的门槛。

## 5.6 定位技术方案

  三级 fallback（location_proxy.py）：
    1. 高德 IP 定位（restapi.amap.com/v3/ip，解析 rectangle 取中心点）；
    2. pconline IP 定位；
    3. ipinfo.io。

  已知局限：IP 定位只能到运营商注册地城市，无法精确到用户实际城市（邢台）；
  解决方案：前端 localStorage 记忆手动选择的城市，一次选择永久生效。

## 5.7 数据需求

  数据库（SQLite）：
    · 车辆数据（车速/转速/胎压等，WebSocket 推送 + 模拟器）；

    · 情绪记录与统计（POST /emotion/records、GET /emotion/stats）。

  模型文件（不入库）：

附：对话中讨论过的关键技术问答要点
================================================================================

  1. 轻量化部署 AI 定位：模型选型偏轻量（EfficientNet-B2、MediaPipe、Haar），
     但大模型/ASR 依赖云端，属"边缘轻量识别 + 云端智能"混合架构，非纯端侧；
  2. OLED / LCD 兼容性：龙芯板卡以 HDMI/USB 输出为主，7 寸 HDMI 电容触摸屏
     （免驱）较稳妥，OLED 无现成接口；
  3. 传感器选型：推荐 USB 免驱设备（麦克风/音箱/摄像头），避免 3.5mm 驱动问题；
     温度/湿度、车辆对接优先考虑 OBD-II（ELM327）或 CAN 总线，龙芯经 USB/串口
     适配；
  4. 语音点歌实现：ASR 识别"播放 XX 的歌" → 意图解析 → 本地曲库/在线曲库检索 →
     全局播放器播放；
  5. 免驱温度检测模块：优先 I2C 传感器（如 DHT/DS18B20）+ 电平转换，或 USB 串口
     温度计；
  6. 高德地图差异化小功能：逆地理编码、城市搜索、IP 定位中心点解析等。
